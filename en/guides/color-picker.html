How to Pick Accurate Colours from Images

A colour looks right in the screenshot but comes out a little off when you sample it. This guide explains where the drift comes from and how to read the true pixel value.

Why colours from screenshots drift

InterferenceWhy the colour becomes unreliable
Browser scalingAbove or below 100%, adjacent pixels are interpolated; you sample an average, not a pixel
JPEG re-compressionSaving a screenshot as JPEG again adds blocking artefacts and chroma subsampling
Display colour managementsRGB and P3 differ, so identical numbers can look different on two screens
Antialiased edgesText and shape edges are blend colours, never the flat colour from the design

The first two are the usual suspects: the image was resampled once before it reached your eyes, so whatever you sample is already a reconstruction.

Which pixel does a pick actually sample

Two kinds of pixels are involved: pixels in the image file, and pixels on your screen. When the browser displays an image larger than its native size, interpolation spreads one source pixel across many screen pixels — sampling there returns the blended result, not the stored value.

So zoom in before picking. At native 1:1 or higher, each source pixel occupies a clear cell on screen and the sample lands on a definite pixel. The coordinate system and magnifier details are covered in the pixel inspector guide.

HEX, RGB and HSL conversions

The same colour has several notations. Take #4f8cff as the example:

NotationValueNotes
HEX#4f8cffShorthand #4f8 doubles each digit to #44ff88; letter case never matters
RGBrgb(79, 140, 255)0–255 per channel: 4f=79, 8c=140, ff=255
HSLhsl(219°, 100%, 65.5%)Hue, saturation, lightness — handier when tuning light and dark steps

In ImageLab, hovering shows both HEX and RGB at once, and a single click copies both notations to the clipboard.

Putting the value into CSS

Store the picked value in a custom property instead of scattering literals:

:root {
  --brand: #4f8cff;
}
.button-primary { background: var(--brand); }

When plugging into a design system, name tokens by role (--brand, --text-link) rather than by colour (--blue) — colour-named tokens go stale the moment the brand colour changes.

Check contrast after picking

A correct colour is not automatically a usable one. Body text needs a contrast ratio of at least 4.5:1 against its background; large text (≥24px) needs 3:1. Those are the WCAG minimums — run the ratio before shipping, don't rely on how it looks.

The picking flow in ImageLab

  1. Open ImageLab and drop an image into the window;
  2. hover: the sidebar and the floating tooltip show HEX and RGB in real time;
  3. click to pick — the value is copied immediately and a toast confirms it;
  4. the pick history keeps the last 18 entries; click any entry to copy it again.

If the file is actually a 16-bit depth map, clicking copies a millimetre value instead of a colour — the right way to read those files is in the depth map guide.

How transparent pixels are handled

The site samples the pixels as finally displayed, with no alpha compositing: a transparent PNG region shows the checkerboard background, so you read that cell's colour rather than the hidden original. When you need alpha-aware sampling, flatten the image onto its background in a design tool first.
