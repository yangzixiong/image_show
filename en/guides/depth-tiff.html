How to View 16-bit TIFF Depth Maps

You have a TIFF that opens as a black or washed-out grey rectangle, and you need the actual depth value of each pixel. This guide explains why that happens and how to read the values in a browser.

A depth map is not a photo

Each pixel of a depth map stores one distance value: how far the sensor was from the surface. The structure matches a photo — same width, height and pixel grid — but a photo uses three channels (R, G, B) for colour, while a depth map uses a single channel for distance.

It is really a numeric table stored in an image format. Opening it with a photo viewer will never show anything meaningful.

Why it looks black when opened

Image viewers render a single-channel file as greyscale: 0 becomes black, 65535 becomes white. An indoor scan with a 2–8 m range has pixel values clustered between 2000 and 8000 — roughly 9% of 65535 — so the whole image squeezes into the darkest end of the ramp.

The data is fine; the rendering is wrong for this kind of file. To see the values themselves you need a viewer that reads raw pixel values.

16-bit vs 8-bit

Bit depthValues per pixelAt 1 unit = 1 mmSuited for
8-bit0–2550–255 mmPreviews, visualisation
16-bit0–655350–65.5 mMillimetre-level measurement
32-bit floatAny decimalRead as metres, ×1000 hereResearch data, wide dynamic range

Storing millimetre-level depth in 8 bits makes adjacent millimetres at 2 m share the same value — the measurement quantises into bands. 16-bit keeps every millimetre distinct across a 65.5 m range, which is why depth maps almost always use it.

Identifying a depth map by its TIFF tags

Check four fields in a terminal with exiftool (or tiffinfo):

$ exiftool scan_001.tif
Bits Per Sample                 : 16
Samples Per Pixel               : 1
Sample Format                   : Unsigned Integer
Photometric Interpretation      : Black Is Zero

The mapping: BitsPerSample=16, SamplesPerPixel=1, SampleFormat=1 (unsigned integer), PhotometricInterpretation=1 (BlackIsZero). When all four line up, the file is a standard unsigned 16-bit depth map.

Unit conventions (how this site reads them)

ImageLab interprets depth values as follows:

  • 16-bit integer: the pixel value is shown directly as millimetres;
  • 32-bit float: parsed as metres and multiplied by 1000 for display;
  • a pixel value of 0 is treated as invalid depth: rendered transparent (the checkerboard shows through) and excluded from the range statistics.

These are site conventions, not an industry standard. Some vendors store 0.25 mm steps, others store metres outright. If the magnitude looks wrong — a desk reading as five digits — suspect the unit before suspecting the data.

Choosing a colormap

Displaying 16-bit values on an 8-bit screen requires a mapping, and the colormap decides what you can see:

ColormapCharacterSuited for
JetHigh contrast, loud bandingLocating structures quickly, demos
ViridisPerceptually uniform, monotonically brighterReading values, paper figures
GreyscaleNo colour biasPrint, aligning with an RGB image

Jet's strong contrast cuts both ways: the perceptual jump between adjacent bands draws a boundary where the values are actually continuous. For quantitative work, switch to Viridis.

Steps in ImageLab

  1. Open ImageLab and drop the TIFF into the window, or click “Open image”;
  2. hover the mouse: the floating tooltip and the sidebar show coordinates and the depth in mm;
  3. switch Jet / Viridis / greyscale in the “Depth settings” panel;
  4. zoom past 14× with the wheel to get the pixel grid; double-click to fit the window.

If you only need the colour of a specific pixel, see the colour picker guide; coordinates and the magnifier are covered in the pixel inspector guide.

What this site deliberately does not do

Some capabilities are left out on purpose to keep the tool dependency-free and fully client-side: no BigTIFF; multi-page TIFFs read only the first page; no point-cloud export; no distance annotation. When you need those, process the data with CloudCompare or OpenCV first, then come back to read the values.
