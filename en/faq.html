Frequently Asked Questions

Straight answers on formats, privacy and everyday use.

Are my images uploaded to a server?

No. Images are read through local browser APIs (FileReader and URL.createObjectURL); the code contains no fetch and no XMLHttpRequest, and your image never leaves your device.

Which formats are supported?

JPG, PNG, WebP, GIF and BMP are decoded natively by the browser; TIFF is handled by the built-in decoder with no compression plus LZW / Deflate / PackBits, covering 8-bit, 16-bit colour and 16-bit single-channel depth maps. Anything else depends on whether your browser can decode it.

How large an image can I open?

There is no artificial size limit; the real constraint is device memory, because each image is decoded into a bitmap in the browser. Slow loading or stutter usually means you are close to the browser's memory ceiling.

Which TIFF compressions work?

None, LZW, Deflate and PackBits. JPEG-in-TIFF, multi-page TIFF (only the first page is read) and BigTIFF are not supported — if a file will not open, re-save it with one of those four compressions first.

What unit do depth values use?

16-bit integer TIFF pixel values are shown as millimetres; 32-bit float TIFF is parsed as metres and converted with ×1000 automatically; a pixel value of 0 counts as invalid depth and renders transparent. Vendor conventions vary, so suspect the unit first when the numbers look absurd. Full details are in the depth map guide.

Why does my depth map open black and white?

Image viewers render single-channel data as greyscale, while depth values usually occupy only a small slice of 0–65535, so the whole image is squeezed into the darkest end. For the file fields and the right way to view it, see the depth map guide.

Why does my picked colour differ from the design?

The usual causes are browser scaling interpolation, JPEG re-compression of screenshots, antialiased edges and display colour management. Zoom to native 1:1 before picking to avoid most of it — see the colour picker guide.

Does it work offline?

All image processing happens locally and needs no network itself, but the first visit must load the page online; after that, whether it opens offline depends on your browser cache (assets are cached for 7 days). There is no offline install package.

Do you store my images?

No. Images are never written to a server or to persistent browser storage; the only local storage used is the language preference imagelab.lang, which you can delete by clearing this site's data in your browser settings.

Is it free? Are there ads?

Free to use, no registration required. The pages currently contain no ads; if any are added later, the privacy page will say so.

Does it work on phones?

The page opens on mobile browsers and you can choose and view images, but canvas panning and zooming are currently bound to mouse events only — touch dragging and pinch zoom are not implemented, so detailed work is better on a desktop browser.

How do I report a bug?

Email yangzixiongh@163.com or raise it at github.com/yangzixiong. When reporting, please include:

  1. Browser and version
  2. Operating system
  3. Steps to reproduce
  4. A sample image that shows the problem
