提示词 Token 计数器

CLIP 为什么是 77 一段

SD1.5 与 SDXL 的文本编码器一次最多吃 77 个 token，其中首尾各有一个特殊 token，实际留给提示词的是 75 个。超长提示词靠 BREAK 切段分批编码，所以这里按 BREAK 分段计数、每段显示 x/77，超出的段会标红——超限部分会被截断，排在后面的画面元素最容易丢。

四套分词规则各数各的

同一段文字在不同模型下的 token 数完全不同：CLIP 有自己的 BPE 词表；T5-XXL 用 SentencePiece，SD3 的上限是 512；o200k_base 与 cl100k_base 是 OpenAI 的 tiktoken 编码，GPT-4o 与 GPT-3.5/4 分别使用。切换模型就换一套词表重新数，CLIP 与两套 tiktoken 用离线词表精确计数，结果与官方实现一致。

词表什么时候加载

四份词表都 vendor 在仓库的 data/tok/ 里，不走任何 CDN；只在打开本页或切换模型时才 fetch，其他页面完全不受影响。词表就绪前数字带「≈」前缀，是按规则估算的近似值；就绪后变为精确计数。T5 的 SentencePiece 词表暂未内置，该模型下始终显示粗估并在状态行注明。
