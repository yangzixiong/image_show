图片取色：取准颜色的完整方法

截图里的颜色看着对，取出来却总是差一点——这篇讲清楚差在哪，以及怎么从原图像素里取到准确的值。

为什么从截图取色经常取错

干扰来源颜色为什么会失准
浏览器缩放非 100% 缩放下相邻像素被插值混合，你取到的是几个像素的平均色
JPEG 二次压缩截图再存一次 JPEG 会产生块效应和色度下采样，纯色区域出现色偏
显示器色彩管理sRGB 与 P3 色域不同，同一组数值在不同屏幕上观感不同
抗锯齿边缘文字和图形边缘是过渡色，不是设计稿里的那个纯色

四个原因里前两个最常见：图在到达你眼前之前已经被重采样过一次，取到的自然不是原始值。

取到的究竟是哪个像素

要区分两种像素：图像文件里的原图像素，和屏幕上显示的像素。浏览器把图片放大显示时，会用插值算法把一个原图像素铺成一片显示像素——这时取色取到的是插值结果，不是文件里的值。

所以取色前先放大：在原图 1:1 或更高倍率下，一个原图像素能对应屏幕上清晰的一格，取色才落在确定的像素上。坐标的定义与放大细节见《像素查看》。

HEX、RGB、HSL 的换算

同一个颜色有多种写法，以 #4f8cff 为例：

表示法写法说明
HEX#4f8cff三位简写 #4f8 每位展开两次，即 #44ff88；大小写不影响结果
RGBrgb(79, 140, 255)每通道 0–255，4f=79、8c=140、ff=255
HSLhsl(219°, 100%, 65.5%)色相、饱和度、亮度；调界面明暗层级时更直观

在 ImageLab 里，悬停会同时给出 HEX 和 RGB，单击一次把两种写法一起复制进剪贴板。

取到颜色之后：写进 CSS

拿到值先放进自定义属性，比散落在各处的字面量好维护：

:root {
  --brand: #4f8cff;
}
.button-primary { background: var(--brand); }

和设计系统对接时建议按语义命名（--brand、--text-link），不要按颜色命名（--blue）——品牌色改版时后者会让所有引用一起过期。

还要检查对比度

颜色取准了不等于能用。正文文字与背景的对比度至少 4.5:1，大字号（≥24px）至少 3:1，这是 WCAG 的最低要求。把颜色写进界面前算一次对比度，别只凭观感。

在 ImageLab 里的操作流程

  1. 打开 ImageLab，把图片拖进窗口；
  2. 鼠标悬停，侧栏和浮动提示实时显示 HEX 与 RGB；
  3. 单击取色，值立刻复制，界面弹出提示；
  4. 取色历史保留最近 18 条，点任意一条即可再次复制。

如果这张图其实是 16bit 深度图，单击复制的是毫米值而不是颜色——那种图的正确看法见《16bit TIFF 深度图》。

透明像素怎么处理

本站取的是最终显示出来的像素值，不做 alpha 合成：PNG 的透明区域显示为棋盘格背景，取到的是那一格显示的颜色，不是被透明度隐藏的原始颜色。需要按透明度感知取色时，先在设计工具里把图平铺到底色上。
