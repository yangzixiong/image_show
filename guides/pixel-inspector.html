像素坐标与放大镜：看清单个像素

屏幕上的鼠标点、图片文件里的像素点、屏幕的物理发光点是三回事——这篇把坐标系、放大镜和缩放锚点讲清楚。

图像坐标系

图像坐标的原点在左上角 (0,0)，x 向右、y 向下——和数学课本里 y 轴向上的坐标系正好相反。取色、读深度、画网格全部用这一套坐标。

坐标指的是像素格子本身：点 (37, 12) 就是第 38 列、第 13 行的那个格子（行列都从 0 开始计数）。和设计稿对位、写切图脚本时，这半行差错会让结果整体偏移一个格。

三种像素

同一个"1 像素"在三个层面含义不同。以 2× 屏（devicePixelRatio = 2）、图片按 100% 显示为例：

名称含义2× 屏上
图像像素图片文件里的采样点，坐标读数以它为准1 个被绘制成 2×2 个设备像素
CSS 像素布局单位，浏览器缩放与 devicePixelRatio 的换算基准1 CSS px = 2 设备 px
设备像素屏幕的物理发光点，你实际看到的最小单位分辨率是标称 CSS 尺寸的 2 倍

这就是高分屏上界面"看起来是 2 倍"的原因：CSS 数值没有变，只是一个 CSS 像素落到了更多物理点上。读像素坐标时永远以图像像素为准，与屏幕分辨率无关。

放大镜

鼠标悬停时，浮动提示旁边的放大镜画出光标周围 11×11 个像素的邻域，每格 16 像素见方。中心格用白色描边标出——取色和确认坐标时看这个框，避免手抖点偏一格。

放大镜内部的绘制显式关闭了平滑（imageSmoothingEnabled = false），所以每个像素块边缘锐利，不会被插值抹开。靠近图像边缘时，越出图像的部分不做镜像补齐，直接保留黑色底：绘制前先把源矩形裁剪到图像边界，取不到的格子自然露出放大镜的底色——看到黑边，说明光标已经贴着图像边界了。

像素网格

缩放到 14 倍以上才会画出像素网格。低于这个倍率时格线会糊成一片，反而干扰判断；到 14 倍每格已有足够的屏幕空间，网格线正好落在图像像素的边界上，配合对齐检查用。滚轮的缩放范围是 2%–6400%，双击图像回到适配窗口。

以鼠标为中心缩放

滚轮缩放时，锚点固定在光标位置：放大之后光标指着的仍是同一个像素，不会滑走。换算只需要一行：

view.x = px - (px - view.x) * (ns / view.scale);

读法：新偏移 = 光标位置 −（光标 − 旧偏移）×（新倍率 ÷ 旧倍率），使光标下的图像点在缩放前后停在屏幕上的同一点。y 方向用同样的式子。

常见用途

  • 切图对位：确认雪碧图边界没有多吃进一排像素；
  • 像素画检查：逐格核对配色与遗漏的杂点；
  • sprite 边界：验证导出图集的对齐与间隔；
  • 还原设计稿：确认 1px 边框在实现里真的只有 1px（要连同设备像素比一起换算）。

深度图的逐像素读数也建立在同一套坐标系上，见《16bit TIFF 深度图》；只想知道某格的颜色值，见《图片取色》。

为什么浏览器原生缩放看不准

浏览器的整页缩放走的是另一条渲染路径：先按布局重排，再对图片插值放大，得到的是平滑后的近似值；而且结果受 image-rendering 属性影响，不同浏览器的默认行为不一致，同一张图在两个浏览器里放大观感可能不同。本站的画布只在缩小时（scale < 1）开启插值，放大时一律最近邻取样——放大到 14 倍再开网格，才是可靠的像素观察方式。
