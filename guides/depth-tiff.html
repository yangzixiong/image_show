如何查看 16bit TIFF 深度图

手上有一张打开后全黑或灰蒙蒙的 TIFF，需要读出每个像素的真实深度值——这篇文章解释成因，并给出在浏览器里直接查看的操作路径。

深度图不是照片

深度图（depth map）的每个像素存的是一个距离值：传感器到物体表面的距离。它和照片结构相同——同样的宽高、同样的像素网格——但通道不同：照片用 R、G、B 三个通道存颜色，深度图只有一个通道存距离。

所以它本质是一张数值表格，只是借用了图片格式存储。用看照片的方式打开它，注定看不到有意义的东西。

为什么直接打开是黑的

看图软件把单通道数值当灰度渲染：0 显示为黑，65535 显示为白。一张量程 2–8 米的室内扫描图，像素值集中在 2000–8000，只占 65535 的约 9%，整张图挤在最暗的一端。

数据没有坏，只是显示方式不对。想知道数值本身，需要一个能读原始像素值的查看器。

16bit 与 8bit 的差别

位深每像素取值1 单位 = 1mm 时适用场景
8bit0–2550–255 mm预览、可视化
16bit0–655350–65.5 m毫米级测量
32bit 浮点任意小数本站按米解析再 ×1000科研数据、大动态范围

用 8bit 存毫米级深度，2 米处相邻的毫米会共用同一个值，测量直接分层。16bit 在 65.5 米量程内毫米不重叠，这是深度图几乎都采用 16bit 的原因。

用 TIFF 字段判断一张图

在终端用 exiftool（或 tiffinfo）查看四个字段：

$ exiftool scan_001.tif
Bits Per Sample                 : 16
Samples Per Pixel               : 1
Sample Format                   : Unsigned Integer
Photometric Interpretation      : Black Is Zero

对应关系：BitsPerSample=16、SamplesPerPixel=1、SampleFormat=1（无符号整数）、PhotometricInterpretation=1（BlackIsZero）。四个都对上，就是一张标准的 16bit 无符号深度图。

单位约定（本站口径）

ImageLab 按以下规则解析深度值：

  • 16bit 整数：像素值直接按毫米（mm）显示；
  • 32bit 浮点：按米解析，显示时 ×1000 换算为毫米；
  • 像素值 0 视为无效深度：显示为透明（露出棋盘格背景），不参与深度范围统计。

注意这不是行业统一标准：有的厂商用 0.25mm 步长，有的直接存米。如果数值量级明显不对（比如桌面距离显示成五位数），先怀疑单位，再怀疑数据。

伪彩色怎么选

16bit 数值显示到 8bit 屏幕必须做映射，伪彩色决定了你能看出什么：

映射特点适合
Jet对比强、层次醒目快速定位结构、演示
Viridis感知均匀、亮度单调递增读数、论文插图
灰度无色偏打印、与 RGB 图对齐叠加

Jet 的强对比是双刃剑：相邻色带之间的感知跳变，会在数值连续的位置"画"出一条不存在的边界。做定量判断时建议切到 Viridis。

在 ImageLab 里的操作步骤

  1. 打开 ImageLab，把 TIFF 拖进窗口，或点击「打开图片」；
  2. 鼠标悬停，浮动提示和侧栏会显示坐标与毫米深度值；
  3. 在「深度设置」面板切换 Jet / Viridis / 灰度；
  4. 滚轮放大到 14 倍以上显示像素网格，双击回到适配窗口。

如果只关心某个像素的颜色值，看《图片取色》；坐标系与放大镜的细节见《像素查看》。

现象可能原因处理

整张图只有一个颜色深度值几乎恒定，范围为 0正常；恒定场景就是单色
数值量级不对厂商单位不是毫米按设备手册换算（如 0.25mm 步长则 ×0.25）
打开失败BigTIFF、JPEG 压缩或多页 TIFF转存为 LZW / Deflate / 无压缩的单页 TIFF
物体边缘出现黑洞传感器在边界无返回，值为 0正常的无效像素

本站不做什么

以下能力是刻意不做的，用来换取零依赖、纯前端：不支持 BigTIFF；多页 TIFF 只读第一页；不做点云导出；不做距离测量标注。需要这些能力时，建议先用 CloudCompare 或 OpenCV 处理，再回到这里看数值。
