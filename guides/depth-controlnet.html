16bit 深度图在 ControlNet 中的用法

深度图是 ControlNet 里「锁结构不锁皮」的通道：它只告诉模型哪里近、哪里远。这篇讲清素材从哪来、单位怎么对、进生成端前要检查什么。

深度通道给模型看什么

ControlNet 的深度模型只接收一张灰度图：越亮越近、越暗越远（个别实现相反，属反相问题，见下文排查表）。它把画面的空间骨架——远近关系、遮挡边界、体积轮廓——注入采样过程，而颜色、材质、光照仍然交给提示词与模型自己发挥。这就是「锁结构不锁皮」：拿线稿能复刻每一笔，拿深度图则是在保住构图的前提下换风格。

通道锁的是什么典型用途
深度 depth远近结构与遮挡关系改风格、换材质，保持机位与摆位
线稿 canny / lineart每一根轮廓线忠实重绘、上色、精细构图复刻
法线 normal表面朝向与光影曲率保持浮雕、曲面细节的重打光

选择经验：构图主要由物体摆放决定时用深度；主要由线条设计决定时用线稿；两者都要时可并挂两个 ControlNet 并各配权重，权重配合见《提示词权重 (a:b) 完整指南》的通用原则——引导过强都会出伪影。

素材的三个来源

来源格式与精度注意
手机 / 相机实拍JPG 灰度预览，或 16bit TIFF 原始深度边缘常有空洞，需看 0 值分布
渲染器 Z-depth 导出16bit 整数 TIFF 或 32bit 浮点 TIFF单位最干净，毫米/米约定要对齐
模型自己生成普通 8bit 灰度图精度最低但零成本，适合草稿

前两类会在浏览器里以原始精度打开——16bit 整数 TIFF 的像素值按毫米显示，32bit 浮点 TIFF 按米解析并自动换算，0 视为无效深度（传感器空洞或渲染未覆盖），显示为透明。完整口径见《16bit TIFF 深度图》，这里不重复。

进生成端之前的两件事

第一，量程与无效值。打开 像素查看器 点几个点：确认数值落在合理距离区间（比如 0.5-8 米），确认半透明的 0 值区域没有占到主体；再用 图片直方图 的深度模式看整体——横轴是毫米，主峰就是场景主体的距离，0 单独统计。0 值堆在主体上意味着那里没有深度信息，喂给 ControlNet 会变成结构黑洞，先补洞或换素材。

第二，归一与分辨率。多数生成端的深度预处理器最终要 8bit 灰度：16bit / 浮点素材需要先归一化到 0-255，把有效量程铺满——这一步通常在生成端的预处理器或外部软件完成，本站工具的边界是查看与验证：帮你确认单位、量程、无效区和黑白方向都对了，再交给生成端。分辨率不用和底图逐像素一致，但构图裁切必须一致，否则结构对不上位。

症状排查表

症状先检查调整
结构完全不跟素材是否真为深度图（有没有被当成彩色图渲染成灰蒙蒙一片）用像素查看器读值确认，或换 8bit 灰度版
远近关系反了素材本身的黑白方向生成端勾选反相，或导出前反转
边缘糊、结构漂移预处理分辨率过低或深度图本身空洞多提高预处理分辨率；看 0 值区域是否侵入主体
画面出现方形黑块无效值 0 被当成「最近/最远」参与计算补洞、裁掉无效区，或换素材
风格被锁死改不动ControlNet 权重过高降权重、放宽引导，参考权重指南的安全区间

在 ImageLab 里的验证流程

  1. 像素查看器打开深度图：16bit/浮点数值、毫米单位、0 值透明，逐点确认量程与单位；
  2. 图片直方图切深度模式：看距离分布主峰与 0 值占比，判断素材可用性；
  3. 需要对照颜色信息时回取色与《像素查看》；全黑打不开、数值离谱这类文件层问题直接查《16bit TIFF 深度图》；
  4. 素材验证通过后，再到生成端挂深度 ControlNet，权重从低往高试。

常见问题

深度图需要和底图同尺寸吗？

构图必须一致，逐像素同尺寸不是硬要求。裁切、留边不一致会直接导致结构错位，比分辨率差异伤害大得多。

为什么打开一半是透明的？

像素值 0 被视为无效深度显示为透明，通常是传感器空洞或渲染未覆盖。占到主体就要补洞或换素材，只是边角则可裁掉。

深度图可以当黑白照片用吗？

不能直接当——它不是亮度信息而是距离信息，直接上色会得到一张「越近越白」的怪图。要可视化请用伪彩或排版处理。

16bit 和 8bit 哪个好？

16bit 量程细、归一后过渡平滑，适合最终出图；8bit 草稿够用。关键是归一化把有效距离铺满 0-255，一半像素挤在暗端等于浪费精度。
